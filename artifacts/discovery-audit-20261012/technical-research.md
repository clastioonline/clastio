# Technical discovery research and implementation — 12 October 2026

Scope: shared canonical URL/metadata helpers, root metadata, robots, sitemap, llms directory, private response headers and a first-party social image. No teacher data, provider credentials or public deployment is changed. The initial working tree was clean. `apps/web/AGENTS.md` requires reading local Next.js documentation first; the installed metadata, JSON-LD, robots, sitemap, route-handler and headers guides were read before implementation.

## Primary guidance used

- Google's current [generative AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), updated 10 July 2026: useful, distinctive content and normal search fundamentals remain central. Generative search requires indexed, snippet-eligible pages and the relevant Search Console inclusion setting. Google ignores llms.txt for search visibility. Special files, invented schema facts and keyword variants do not guarantee rankings or citations. Search Console setup/reporting remains an owner-side operation, not something this code silently enables.
- Google's [sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap): use absolute canonical URLs; lastmod should describe significant actual page changes, not the time a sitemap was generated. Google ignores priority and changefreq.
- Google's [robots introduction](https://developers.google.com/search/docs/crawling-indexing/robots/intro): robots controls crawling, while noindex or authentication controls indexing/access. A disallow is not a security boundary.
- Microsoft's [sitemaps in AI search guidance](https://blogs.bing.com/webmaster/2025/7/Keeping-Content-Discoverable-with-Sitemaps-in-AI-Powered-Search/): accurate modification dates and a sitemap reference help discovery; neither sitemaps nor submission guarantee visibility.
- [OpenAI's crawler documentation](https://developers.openai.com/api/docs/bots): OAI-SearchBot serves search, GPTBot addresses foundation-model training, and their choices are independent. ChatGPT-User represents user-triggered visits and is not the automatic search crawler. Hosting/CDN rules and published crawler IP ranges also matter beyond robots.
- Installed Next.js docs: root metadataBase resolves relative URLs; nested metadata is shallowly replaced; absolute titles bypass a parent's title template. Use a native JSON-LD script and escape `<`. Special robots/sitemap handlers are cached by default; a regular GET handler can explicitly opt into static generation.

## Findings and changes

1. **Canonical configuration:** the old helper only trimmed trailing slashes. The helper now validates HTTP(S), rejects credential-bearing origins, normalizes the configured origin and removes path/query/fragment pollution. Internal canonical paths cannot switch origins. `NEXT_PUBLIC_SITE_URL` still must be set correctly at the production frontend build; localhost build arguments are intentionally preserved for local testing.
2. **Titles and social cards:** the old title template could duplicate Clastio when callers already included the brand. Public metadata now emits an absolute title with the brand once, matching OpenGraph/Twitter. A 1200×630 first-party PNG replaces the square logo as the share card, with a large-image Twitter card, dimensions and useful alt text. The original brand assets remain unchanged. The SVG is the code source; the PNG is the served metadata image.
3. **Public/account boundary:** root metadata defaults to noindex; public pages explicitly opt in using pageMetadata. The shared private prefix list includes newer books, digital-library, copilot, lesson-planners, demo-classes and rewards routes, plus login/signup/password/account/API paths. The same list supplies robots and HTTP noindex headers, reducing drift. Authentication still protects actual teacher resources.
4. **Rendering resources:** the broad API crawl block previously covered the public JSON used to render pricing, legal content and status. Narrow allow rules now permit `/api/v1/billing/plans`, `/api/v1/legal/*` and `/api/v1/status` while account APIs remain disallowed. Raw API responses retain noindex headers; fetching public data does not make private data public.
5. **AI crawler policy:** explicit OAI-SearchBot rules carry the same private exclusions and public rendering exceptions as the wildcard group. The existing public training crawl preference is preserved; no GPTBot policy is silently changed.
6. **Sitemap:** all guides and public information pages derive from the existing content inventories, including the three approved new buyer/specification/cost guides. Duplicate canonical URLs are removed. Only real guide reviewedAt dates become lastModified; other pages omit unknown dates. No request/build timestamp or invented update date is used, and ignored priority/change-frequency hints were removed.
7. **llms directory:** this existing route now derives its public links from the same inventories, includes reviewed dates only where available, and clearly describes teacher review, actual specification input, textbook permissions and private access. It is a static public text directory with noindex, not a Google ranking mechanism or authorization to read account data.
8. **Truthful identity graph:** Organization/WebSite/SoftwareApplication share stable references. No address, legal company identity, social profile, rating, review, offer or exam-board approval is invented. The homepage owns the single graph; the root layout does not duplicate it.

## Verification scope

The four new shared-helper checks cover invalid/credential-bearing origins, stable same-origin canonicals, title/card consistency, newer private route inventory, safe JSON-LD serialization and absence of invented business/review facts. The PNG was rendered locally from vector code and the existing favicon, visually inspected, and measured as 1200×630 (75,456 bytes). Final consolidated TypeScript/build/browser verification is coordinated by the root agent after all page-content and pricing edits freeze.

Actual indexing, search traffic, AI citations, Search Console/Bing ownership, public CDN crawler access and deployed canonicals are external verification steps. No search or AI visibility result is claimed from local source changes.
